# ETH Cali Wallet — Project Conventions

app.ethcali.org. The workspace rules (chain is the source of truth for money, load the
`ethskills` skill first, verify addresses on chain) are in `../CLAUDE.md`. Feature rules load
on their own when you touch their files — see "Feature rules" below.

## Verification (mandatory)

```bash
npm run typecheck   # tsc --noEmit: strict, noUnusedLocals, noUnusedParameters
```

Nothing is done until it passes. `npm run lint` currently crashes on a circular ESLint config
(pre-existing); do not treat that as your failure, and do not treat it as a pass either.

## Stack

Next.js 16 (Pages Router, Turbopack) · TypeScript strict · Tailwind on `@ethcali/design-tokens`
(dark-only) · Privy (`@privy-io/react-auth`) · viem 1.x (not ethers) · TanStack Query for server
state · Supabase (project `ethcali`, ref `eaiksxifsxtxnlpmlzyq`) · Vercel (team Ekinoxis,
project `wallet-ethcali`).

## Layout

```
pages/        routes; pages/api/** server routes      components/<domain>/   UI
hooks/<domain>/index.ts  barrel per domain               lib/                   server integrations
config/chains.ts  the one chain registry                 types/                 shared types
frontend/     GENERATED by `npm run sync:contracts`      supabase/migrations/   one file per migration
docs/         runbooks (CERTIFICATES.md, SWAG_ORDERS.md) and contract references
```

## Chains

**Ethereum mainnet only** (owner decision 2026-09-23). Base is in the registry solely for the
`ethcali.eth` registrar. No chain picker, badges or per-chain breakdowns; adding a chain is a
deliberate change, not a flag.

- `config/chains.ts` is the only place a chain id, RPC, explorer, token or contract address is
  written. New code imports from it, not from `config/constants.ts`.
- Every read takes an explicit chain id: `publicClientFor(id)`, never the wallet's provider.
- The wallet is switched lazily, right before signing: `useRequireChain(chainId)`; while
  `!ready` the only primary action is `SwitchChainButton`. Use `useActiveWallet()`'s wallet,
  never `wallets[0]`.
- `getChain(id)` returns `undefined` for an unsupported id and the UI says so. No silent fallback.

## Contract calls

- Reads: `useQuery` + `publicClientFor(chainId).readContract()`.
- Writes: Privy `useSendTransaction` + viem `encodeFunctionData`, explicit `chainId`,
  always `{ sponsor: true }`, after `useRequireChain(chainId).ready`. Invalidate queries after.
- Each onchain button owns its pending state, cleared in `finally` (see ethskills `frontend-ux`).
- Sponsored writes go through Privy's ERC-4337 relay and can report an error for an operation
  that landed. Before telling a user a write failed, re-read the chain.

## Rules

1. **`frontend/` is generated.** Never hand-edit; `npm run sync:contracts`, commit the result.
2. **No dead code or exports.** Delete unused files, imports and types; update barrels.
3. **Migrations twice.** A schema change is a file in `supabase/migrations/` *and* applied to the
   project (Supabase MCP `apply_migration`, same name). Never one without the other.
4. **Admin authority is on chain.** Server routes check roles with `hasRole`; tables like
   `admins` or `swag_staff` only decide what is shown.
5. **Never `npm audit fix --force`.** Transitive issues go in `overrides`; pin `next`, `react`,
   `react-dom` exactly.
6. **Prefer editing over creating;** keep user and admin flows in separate hooks/components.
7. **When contract functions change,** check the `docs/` references.

## Rendering gotcha: no on-demand server render of a page that imports Privy

On Vercel, Privy loads as an external ES module whose `styled-components` import Node rejects,
so a page rendered per request (`getServerSideProps`, `fallback: 'blocking'`) answers 500 while
the same page prerendered at build works. `_app` mounts Privy, so this is every page.
Prerender with `fallback: false` and every path listed; new paths appear only after a deploy
(certificates trigger one through `VERCEL_DEPLOY_HOOK_URL`). URL normalisation lives in
`proxy.ts` at the edge. `transpilePackages` for Privy breaks the Turbopack build.

## Pull requests

- Branch from `main`, one concern per PR, commit messages say why.
- Hand the owner the **Vercel preview URL** of the branch (and the exact page to open), not
  only the GitHub link — they review by using the page. Wait for the preview to be READY.
- The owner merges, or asks for the merge explicitly.
- Every feature ends with a docs pass: this file, the matching `.claude/rules/*.md`, the
  runbook in `docs/`, and the README if a human-facing behaviour changed.
